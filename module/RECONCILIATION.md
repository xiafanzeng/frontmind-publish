# 发布认证、状态核对与资金处理

业务实现位于本子仓 `module/server/providers/kol/`、`module/worker/`、
`module/server/publisher-worker-repository.ts` 和 `module/server/publisher-repository.ts`。

## 正常发布

1. 确认稿件、媒体与报价，预占本批金额。
2. Worker 在付费订单 POST 之前执行只读认证预检。已有 token 失效且账号配置完整时，先在安全 GET 阶段刷新。
3. 预检通过后，订单 POST 只发送一次。返回订单号后保存订单号，后续仅查询该订单。
4. 发布成功结算；明确失败退回预占；无法确认是否已成单时保留冻结并进入核对。

## 认证会话

发布 Worker 是该运行环境唯一的自动登录和 token 刷新入口。网页的连接检查通过队列交给同一个 Worker，复用实际发稿进程的会话；检查只读订单列表，不发稿、不预占、不扣费。

API 不再用独立短生命周期客户端自动登录。旧的同步连接探针仅验证现有 token，不替 Worker 刷新。媒体要求采集也通过同一 Worker 执行，只读取指定目录页，并在事务中更新规则快照与目录版本。并发采集按分钟和页码合并，API 仅读取该任务的明确结果。

并发点击连接检查按分钟合并，本次检查按 checkId 读取结果，不能把历史健康状态当成本次成功。

单会话供应商的网页重新登录仍可能撤销 API 会话。长期应使用供应商支持的独立 API 凭据或专用账号；若供应商支持幂等下单号及按该编号精确查询，应在此模块接入，缩小请求中断时的不确定范围。没有供应商承诺时，不自动重发付费 POST。

## 失败边界

- 发送前的参数、配置、认证预检失败：没有订单 POST，释放预占，显示可操作的失败提示。
- 调用订单 HTTP 接口后超时、响应丢失、含糊响应或认证异常：保存发送阶段、错误码与 HTTP 状态，进入待核实。不能从 fetch 异常反推字节未发出，也不能仅凭 401 推断供应商一定未建单。
- 原始请求结果和资金流水保留，不修改历史证据来消除错误。

## 对账与管理员处理

只读对账按原始发送尝试的时间寻找同媒体、同标题候选，保存检查时间、页数、供应商报告的末页和覆盖是否完整。未解决项目定期继续检查；旧版本已经完成但未结案的查询任务会恢复。

订单列表为空、缺少分页、只查到前几页或没有候选，都不等于供应商确认没有订单。当前接口没有强一致的未成单证明，因此不据此自动退款。

- 找到已核验的真实订单：绑定订单号后继续只读查询。
- 供应商明确确认未创建订单：管理员填写核验说明和依据，选择“确认未成单并退款”。系统锁定对应尝试和资金记录，在同一事务退回预占、关闭项目及批次、保存核对记录；重复请求不重复退款，也不重新发稿。
- 有疑问：继续冻结并保留待办。

发布记录顶部显示冻结告警及退回说明。管理员界面每 15 秒刷新待办和冻结金额；这部分界面属于 Dashboard，需随 Dashboard 发布才能在管理员入口生效。子域名发布会更新业务 API、Worker、客户提示和连接检查，不自动发布生产 Dashboard，也不改变管理员授权。
