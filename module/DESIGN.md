# 信源规划界面约定

## 2026-10-26 检查表五列与冻结正文弹窗（当前约定）

本节仅覆盖预检检查表的媒体展示、列宽、行背景及冻结正文查看方式，优先于下文四列/Logo/行内正文约定；沿用既有手动预检、冻结版本、费用及受理保护规则。

- 检查表由 `ReviewPage.tsx` 和 `publishing.review-batch.css` 拥有：媒体名称、媒体类型、发布标题、内容检查、状态五列。媒体名称不带 Logo/占位，类型使用真实 kind 原映射（self_media=自媒体，news=软文媒体，未知=媒体类型待核验）；不恢复媒体号展示，不改变媒体身份或请求。
- 桌面列宽 `minmax(0,1fr) 104px minmax(0,1.25fr) minmax(0,1.45fr) 104px`，横向间距16px、行内距18px/24px；类型与状态紧凑，标题和检查说明占主要宽度。可用表宽<=860px或视口<=900px按完整五字段纵排，内距16px、显示字段名；不隐藏检查内容、缩字体或影响整页滚动。
- 表头使用既有 `--publishing-canvas`（#f5f6fa），稿件分组整行使用 `--publishing-purple-soft`（#f9eff5），普通数据行使用 `--publishing-surface`。文字使用 `--publishing-ink`，分隔线沿用 line，不给单列染色。全部规则局限预检检查表。
- 每稿“查看冻结正文”打开 `PublishingFrozenArticleDialog`，薄包装现有 `@frontmind/module-ui/components/ui/dialog`，复用帮助入口同一 Radix Dialog/Portal/主题/遮罩/焦点机制，不改确认发布弹窗或 vendor。移除行内正文及收起状态；正文、标题、版本/hash只来自当前有效 `preflight.article`。
- 预览选择只保留 draftId、真实草稿上下文、检查代次与触发按钮，正文每次由当前检查结果派生。上下文或预检失效时关闭；预检前维持禁用和原因提示，不自动预检，不读取可变编辑正文。单稿/批量/同名稿件不按名称或位置关联。
- 弹窗使用专属 Portal 样式，复制触发按钮已解析的 publishing tokens/字体，缺失时回退现有品牌值。正文内部滚动，标题/版本/关闭区保持可达；明确关闭按钮、Esc和焦点约束由共享 Dialog 承担，关闭焦点使用 preventScroll。弹窗开关不重置预检、确认或页面滚动入口。
- 本轮仅源码修改/阅读自查。新增与更新的测试源码、实际五列计算样式、弹窗焦点/遮罩/长内容/滚动及桌面窄屏截图由 ZCode 在最终合并版本执行。没有依赖、全局样式、宿主或部署变更；Dashboard实际导入及运行范围仍须集成方确认。

## 2026-10-25 手动预检与准备页进入位置（当前约定）

- 普通未提交投放进入或重新进入预检时，只读取真实草稿与必要元数据，状态为“待预检”、内容检查为“—”；旧结果不持久化为新的发布许可。唯一“一键预检”使用现有 `publishing-button-primary` 与品牌 tokens，位于检查区顶部。点击才调用真实预检，过程、部分失败、失败重试和过期响应均有明确状态。

- 两页进入时由模块内共享滚动 hook 定位页面祖先的实际滚动容器回顶，并在首次异步就绪时有限补位；用户开始操作后停止补位。普通输入、勾选、预检结果更新和正文展开不重新回顶；不改全局 history.scrollRestoration，不改宿主/vendor 滚动布局或焦点。
- 费用预算仍在全部检查组之后；未取得完整当前预检时正式总价/预占明确待核验，不把未知金额当免费。原顶部面包屑、模式分流、确认流程及页面外留白继续沿用。
- 本轮仅源码修改、阅读自查和打包。未运行样式审计、类型检查、测试、构建、应用、浏览器或业务 API；实际计算样式、滚动、键盘及网站验收交由 ZCode。Dashboard 宿主装配未随包提供，不能声称已同步或上线。

## 2026-10-25 标题模式与预检布局（当前约定）

本节按本轮用户两张截图及准确输入包要求，更新下文历史标题/预检描述中的重复模式选择和费用置顶规则；其它页面的品牌、导航及业务约定不变。

- 模式唯一来源是稿件阶段的决定与已保存 draft.titleMode。single/per_media 是标题语义，编辑器 single/multi/batch 是组织方式；已有多稿不得按数量覆盖每稿模式。选媒成功保存必要标题后，全 single 直接预检，有 per_media 才进配置区；标题页无模式切换，混合既有集合只编辑 per_media，单标题仍保留在完整预检集合。旧模式缓存不反向覆盖服务器新选择。
- 标题页复用既有 TitleEditor、稿件×冻结版本×媒体的关联与取消快照。缺失正式共享标题须回稿件确认，不以展示名称/文件名猜测。表格背景归 publishing.titles.css：本表 thead/tbody 行用 surface，正文 th/td 继承整行背景，局部覆盖宿主全局 th 的浅色；取消背景应用整行。Logo、类型标签、错误和输入焦点保留。五列宽度、900px 内部滚动、24px/16px 卡内距沿用既有值，无右侧摘要。
- 预检正文移除两条完成提示、重复大标题及描述的组件包装。PublishingPage 的 review 变体仅取消重复 heading/intro，保留主内容名称、加载语义及 page class；默认变体不变。DraftConversation 的 review 直接渲染业务页，统一顶栏面包屑仍由 URL 显示当前阶段。
- 实际 DOM 顺序：一个“发布内容检查”区域（全部稿件组、冻结正文、结果）→一个汇总费用卡→原确认与底部操作。唯一全局预检按钮在检查区域顶部，沿用原 reload、确认失效、进行中和未知请求处理；不在各稿或底部重复。工具栏 flex 自动换行，间距12px/20px，按钮最小136px；检查区标题沿用17px。原检查组18px/24px间隔、区块22px间隔、费用卡20px/24px内距不改。
- 外层仍由 PreparationContentLayout 拥有：最大正文1520px，桌面26px / clamp(24px,2vw,32px) / 38px；<=720px 为18px/16px/28px。无需新增空白壳或全局 reset，不修改浏览器缩放、字体、共享 vendor、侧栏/搜索/帮助。
- 预检返回由当前待修改稿件的真实 titleMode 决定：全 single 回选媒，有 per_media 回标题。单标题三步、多标题四步；不为 flow 宿主新增第二条步骤。预检接口省略 titleMode 时，只读同版本/同修订草稿补足导航上下文，原预检快照仍保持原样供提交核验。
- 已受理与未知请求在同工作区/任务内按真实 draftId 恢复，集合或排除参数改变不能解除保护；未知请求保留原幂等载荷。已受理稿件从返回修改集合及稿件版本参数中移除，不重新计费。费用精度、服务端报价、确认、逐稿预检/提交和授权不改。
- 所有业务改动位于 module/ 的真实引用链，standalone 继续消费模块入口；没有改宿主共享外壳或部署。Dashboard 是否消费这些入口和任务持久值，须由其集成方确认，不能从独立站源码推定主站已更新。
- 本轮未执行运行验证，交由智谱 ZCode 和网站验收。源码阅读、未执行的回归用例与包内容核对不代表类型检查、测试、构建、计算样式、键盘、窄屏或上线验证通过。

## Components and behavior

- 表单：业务拥有校验与文本错误；noValidate；每个字段关联 label；金额输入 text/inputMode=decimal；提交中防重复。
- Select：本功能采用浏览器原生 select，明确接受平台弹层尺寸和键盘行为，无自绘弹层。
- Navigation：wouter + projectWorkspaceUrl，task 查询参数恢复服务器任务；不把品牌/租户放到用户可编辑绑定中。新增入口仅挂在 PublishingRoutes 的工作台路由，不修改 WorkbenchPage。
- Feedback：复用 PublishingError/Loading/Empty，新状态使用页面内 role=status/alert，无新弹窗。草稿保护复用现有 host.useDraftGuard。
- Data table：只读语义 table；横向滚动保留窄屏列信息。环图仅使用当前完整范围的域名分布，未知分母不画比例。
- 数据状态：未配置、等待模型、处理中、取消、过期、错误均有文本；预算可行、预检与正式发布就绪分开。加入是预算偏好，不是购物车。
- 异步：同源凭据；AbortController 与请求序号忽略旧响应；有限轮询，超时提供刷新；取消标记会阻止结果落库。
